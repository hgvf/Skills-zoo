# Validation Rules

## 1. JSON 格式

- 必須為合法 JSON。
- 不得包含 Markdown code fence。
- 不得有 trailing comma。
- 所有 key 與字串必須用雙引號。
- 不得新增 Schema 外欄位。
- 缺失值用 `null`，缺失陣列用 `[]`。

---

## 2. 數字一致性

檢查：

- 產品或部門營收占比是否合理。
- 同一維度占比總和若接近 100%，允許四捨五入誤差。
- 不同維度不可互加，例如產品占比不可與地區占比相加。
- 毛利率變化使用 percentage point。
- YoY 計算基準一致。
- FCF 僅可使用公司揭露值，或 OCF 減 CapEx。

---

## 3. 時間一致性

- 過去年度成果不得放入未來研發。
- 尚未量產產品不得標記 `mass_production`。
- 管理層規劃不得寫成已完成。
- 預計時間必須保留原文件語氣，例如「預計」、「目標」、「可能」。

---

## 4. 實體一致性

- 公司名稱、Ticker、地區不得混淆。
- 客戶、供應商、合作夥伴、競爭者的角色分開記錄。
- 匿名客戶不得擅自實名化。
- 推論的公司必須標記 `inferred`。

---

## 5. 證據完整性

重大欄位必須有 `source_reference`：

- 營收占比
- 實名客戶與供應商
- 產能與稼動率
- 研發成果
- 量產與客戶驗證進度
- 競爭者
- 公司困境
- 重大風險
- 管理層未來目標

---

## 6. 完整度評分

`completeness_score` 範圍為 0～100。

| 分數 | 判定 |
|---:|---|
| 90～100 | 財務、產品、研發、客戶、供應鏈、競爭與風險完整 |
| 75～89 | 核心財務完整，但部分客戶或產品占比缺失 |
| 50～74 | 只有部分章節或資料顆粒度不足 |
| 0～49 | 文件不完整，重大判斷需大量推論 |

---

## 7. 最終檢查清單

- [ ] 文件年度正確
- [ ] 幣別正確
- [ ] 公司與代號正確
- [ ] 產品階段沒有誤判
- [ ] 營收占比維度沒有混用
- [ ] 實名公司均有來源
- [ ] 已發生困境與未來風險已分開
- [ ] 外部研究與年報內容已區分
- [ ] 所有重大結論有證據
- [ ] JSON 可通過 Schema 驗證
